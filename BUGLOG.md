# Skill Passport bug hunt log (Round 3, run on Instinct sandbox)

## BUG-1: First-time visitor trapped by sign-in modal
- Repro: open / with no stored session. "Demo sign-in" modal opens automatically (auth.tsx: isLoginModalOpen = !user). Close button in LoginModal.tsx renders only when `user` is truthy (line ~113 `{user && (...)}`), so a new visitor cannot dismiss it and cannot reach the Create Passport form without signing into a demo profile.
- Impact: Round 3 "a stranger can finish the main journey" - main journey blocked at step 0.
- Fix: render close button unconditionally.
- Status: fix pending verification.

## BUG-1 UPDATE (fixed + verified live)
- Second root cause: auth.tsx closeLoginModal had `if (user)` guard - deliberate sign-in wall. Both the conditional X render AND the guard removed; modal still auto-opens but is dismissible.
- Verified live: fresh logged-out visit -> X renders -> click -> modal gone -> form interactive. npm test: see run. tsc clean.

## BUG-2: Default Gemini model hangs on generateContent (new API keys)
- Repo default GEMINI_MODEL=gemini-flash-latest. With a freshly created Gemini key, POST :generateContent to v1beta/models/gemini-flash-latest never responds (connection open, no bytes, >60s). gemini-3.8-flash same. gemini-2.5-flash returns 404 "no longer available to new users". gemini-3.5-flash-lite works (200, <1s).
- Impact: passport generation would hang until timeout for anyone deploying with a new key and the default model. Judges cloning the repo with a new key hit exactly this.
- Local workaround applied in .env: GEMINI_MODEL=gemini-3.5-flash-lite. Recommend changing the repo default/README; needs a real-generation check to confirm quality is acceptable.
- Status: workaround verified at API level; full pipeline check pending valid GitHub token.

## BUG-3: Certificate/report pickers accepted any file type client-side
- Repro: set a .txt on the Certificates input -> listed as selected, no complaint. accept attribute only filters the native dialog; onChange trusted everything. Server does reject bad magic bytes (415), so no data corruption - but a user who flips the dialog to "All files" gets a late server error instead of instant feedback.
- Fix: onChange filters by MIME/extension for both Certificates and Project reports, shows "must be PDF, PNG, or JPEG files. Unsupported files were not added."
- Verified live: .txt now rejected with message; 46/46 frontend tests pass; tsc clean.
